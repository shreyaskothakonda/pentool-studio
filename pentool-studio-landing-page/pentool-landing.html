02 Why

Handing a Figma file to a developer, or to an AI, loses almost everything that made it a design.

A screenshot loses the tokens. A code export loses the component structure. Figma's own MCP server hit a Starter-plan ceiling mid-project and stopped working. And the usual AI answer — paste a screenshot and hope — gives you hardcoded hex values, invented class names, and markup that ignores the design system the site is built on.

Meanwhile the knowledge that makes a rebuild correct lives nowhere durable: which components already exist, which classes are in the style guide, that set_text silently does nothing on a DivBlock. It lives in the head of whoever built the site last, and it gets rediscovered every time.

03

Not a design-to-code exporter.

An exporter gives you
—A pile of markup to reconcile by hand
—Hex values where your tokens should be
—New class names nobody asked for
—Components rebuilt from scratch
pentool.studio gives you
+Instructions for extending the site you have
+Variables resolved to their token names
+Your style guide's classes, marked existing or new
+Existing components reused, not duplicated
It starts from what you already built — your classes, your components, your tokens — and writes the design in those terms. What comes out is not a new site. It is instructions for adding to yours.

→

Every decision in here is shaped by what Webflow's API can and cannot do.

It builds through the official Webflow MCP — the same connection you already authorise — so classes, elements and CMS bindings are created the way the Designer would create them, on the site you already have.

And where the platform has no answer, it says so instead of improvising. Three missing endpoints explain almost every design decision in the product:

No undo API

So it builds a single section, then stops and waits. A wrong class costs one section, not a whole page.

No backups endpoint

So it asks you for a Designer restore point, and keeps a diffable snapshot of pages, styles and components instead of pretending it can restore one.

No IX3 API

So captured prototype wiring comes back as a manual to-do list, never as an interaction it claims to have built.

Official MCP

Elements, classes and CMS bindings written through Webflow's own MCP server, with your permission prompts in the loop.

Client-First native

Client-First v2.1 or Relume v3.0, set in one code block rather than a settings screen. Classes come from the style guide you describe there, dimensions in rem, hairlines in px.

Staging, never live

The visual check publishes to your .webflow.io subdomain. Going to production stays your click.

06

Six things it does. All of them are built.

01

Reads the design properly

Not pixels — structure. Tokens bound to spacing, padding, radius and colour. Component properties. Mixed-run typography. Prototype wiring. Auto-layout, including what Figma infers for hand-positioned frames.

Variables resolve to their token names, not to hex values.

02

Uses the class names you already have

Class names checked against your real style guide — [existing] when the class is already there, [new] with the CSS to create it. Every dimension in rem, hairlines in px.

Your inventory — component list, class list, size scales — lives in one code block you edit. Describe a site there and [existing] starts meaning something for it.

Nothing invented. Nothing hardcoded.

03

Knows what not to rebuild

Components you have already built come through as reuse, do not rebuild, so the agent places an instance instead of duplicating the markup.

One master, three instances, no fourth copy.

04

Checks accessibility as it goes

It has the text colour and the background in hand at the same time, so it works out the contrast ratio itself instead of asking you to. Plus missing alt text, icon-only buttons with no accessible name, tap targets under 44×44, and skipped heading levels.

Contrast computed, not flagged for a human.

05

Builds one section at a time

Then it stops and waits. Webflow has no undo API, so a wrong class costs one section, not a whole page.

It stops on its own. You say when to carry on.

06

Checks its own work

After building, it publishes to staging, screenshots the live page, and compares it with the Figma export. The comparison needs the plugin's preview-PNG option switched on — it is off by default, so you opt into it per capture.

Staging only. Differences listed, side by side.

07

Worth knowing.

It uses your Claude subscription

Not an API key, not separate billing. The app spawns the CLI you already have — so your Webflow connection, your skills and your settings come with it.

Nothing is published without you

The visual check publishes to the .webflow.io staging subdomain only. Going live is never automated.

Every session takes a snapshot first

A structural record of pages, styles, components and element trees, so you can diff exactly what a build changed.

It refuses rather than guesses

A missing MCP tool, an unresolvable class, a page that does not exist — each is a stop with a reason, not a best effort.

08

Honest limits.

Seven things it does not do. Read them before you install it.
L—01

It has not built a live site yet

The whole path is written, validated and tested end to end, but nothing here has run against the live Webflow API — no class creation, no asset upload, no element insertion. There is no sites-built number on this page because there is no honest one.

L—02

Your style guide has to be described first

It knows the class list you gave it, not Webflow's universe of classes. The shipped inventory is one specific style guide; another site needs its own before [existing] means anything.

L—03

A snapshot is not a backup

Webflow's API has no backups endpoint, so nothing here can restore a site. The snapshot is a diffable record; the recoverable backup is Webflow's own restore point, which you create in the Designer. pentool.studio asks for one and writes down whether you said yes.

L—04

Interactions cannot be automated

The plugin captures your prototype wiring, but neither Webflow's MCP nor its Data or Designer API can create IX3 interactions. Hover and click states are logged as a manual to-do.

L—05

One agent per project

Projects run in parallel safely. Two agents on one site would race on class creation and element insertion, which Webflow has neither transactions nor undo for.

L—06

It cannot write your alt text

It knows an image needs one; it does not know what the image means.

L—07

Class names are proposals

Derived from your Figma layer names, and marked [name inferred] when the layer was called Frame 7 and the name had to come from structure instead.
